CC5: Skills & Slash Commands

Build custom commands as unified skills; use SKILL.md, shell injection, and fork execution.

The Big Idea

Custom commands and skills merged into one system. A skill is a directory with a SKILL.md file containing YAML frontmatter and a prompt body. Old .claude/commands/*.md files still work as degenerate skills. Skills live in 4 scopes (Enterprise, Personal, Project, Plugin) with inheritance rules. You can inject live shell data, run skills in isolated fork contexts, and access 6 substitution variables. New work gets the full skill upgrade; old work keeps running unchanged.

Analogy

Your kitchen used to have two recipe systems: index cards (one-pagers) and binders (multi-page playbooks with prep notes and photos). Both produced dishes; the split forced you to choose format per task. Then cards evolved: stick a card in a folder, optionally add supporting files, same place and name, just more capacity. That's the merge—old cards still work, new ones get the upgrade for free.

How It Works

  1. Create .claude/skills/my-skill/ directory with SKILL.md inside.
  2. Write YAML frontmatter (description, allowed-tools, context, etc.) and a Markdown prompt body.
  3. Trigger via /my-skill (slash command) or let Claude auto-invoke if description matches context.
  4. Use substitution variables ($ARGUMENTS, $N, $name, ${CLAUDE_SESSION_ID}, ${CLAUDE_EFFORT}, ${CLAUDE_SKILL_DIR}) in the prompt.
  5. Optionally inject shell output with !`cmd` syntax, isolate via context: fork, or pre-approve tools with allowed-tools.

Pseudocode

IF slash_command_typed THEN
  Lookup skill by name in hierarchy: Enterprise > Personal > Project
  IF skill found THEN
    Render SKILL.md: substitute arguments, execute !`cmd` blocks, interpolate variables
    Send rendered prompt to Claude
    IF context: fork THEN
      Run in isolated subagent; return summary only
    ELSE
      Run inline; tool calls visible in main context
    END
  ELSE
    Try old .claude/commands/name.md (backward compat)
  END
ELSE IF Claude_decides_to_auto_invoke THEN
  Match description against context; fire if confident
END

Common Misconceptions

  • Myth: allowed-tools blocks other tools. Reality: It only pre-approves those listed; Claude can still call other tools (they trigger permission prompts). To actually deny, use permissions.deny.
  • Myth: !`cmd` is executed by Claude during tool calls. Reality: It runs at skill render time, before Claude sees the prompt; output is inlined as static text.
  • Myth: context: fork works without a task. Reality: Fork isolation only works if the skill has a clear task; pure reference content should run inline so Claude uses it alongside your conversation.

Key Takeaway

Skills unify commands and enable team playbooks. Drop a SKILL.md anywhere in the 4-scope hierarchy and Claude picks it up live. Use fork execution for isolated research, shell injection for live data, and substitution variables to parameterize reusable prompts. Skills convert tribal knowledge into checked-in artifacts your whole team runs consistently.

Quick Quiz

Q1. You have .claude/commands/deploy.md and your teammate adds .claude/skills/deploy/SKILL.md. What runs when you type /deploy?

A) Error—name conflict.
B) The command (older) wins.
C) The skill wins; skills take precedence over same-named commands.
D) The most recently modified file wins.

Answer: C — Skill takes precedence. Old commands keep working, but if both exist at the same scope, skill wins.

Q2. Your skill needs the GitHub PR diff inlined into the prompt without a tool round-trip. What is the right syntax?

A) {{ gh pr diff }}
B) !`gh pr diff` — inline shell injection
C) $(gh pr diff)
D) Not possible; tools must round-trip.

Answer: B — !`cmd` runs at render time and inlines stdout. For multi-line, use a fenced ```! block.

Q3. A skill must do thorough codebase search but you do not want all file contents flooding main context. What do you set?

A) disable-model-invocation: true
B) allowed-tools: Read
C) context: fork with agent: Explore
D) Move it to ~/.claude/skills/

Answer: C — Fork isolation = context: fork. The Explore subagent type is read-only and tuned for codebase search; only the summary returns to your main session.
