CC8: Tool Use Deep Dive

Master the four-step tool-use loop, multi-tool orchestration, and fine-grained control.

The Big Idea

Tool use transforms Claude from a text-only model into an agent. The mechanism is a four-step loop: your app sends Claude a user message plus tool definitions; Claude responds with a tool_use block (decide to call); your app runs the tool and returns results; Claude integrates and answers. This loop repeats until done. Every Claude Code action — reading files, editing, running Bash, searching — is tool use under the hood. Understanding this loop is understanding how agents work.

Analogy

Imagine a doctor diagnosing without ordering tests — just guessing from symptoms. Now give that doctor a lab next door: order a CBC, get results, decide. Slower per question, dramatically more accurate. Tool use is the lab. Claude alone is the doctor without one; with tools, Claude can look things up, run code, edit files, query databases. Each tool call is an order; the result comes back and Claude integrates it.

How It Works

  1. App defines tools (name, description, input schema) and sends user message + tool list to Claude.
  2. Claude responds with tool_use block containing tool name and input. Stop reason becomes "tool_use".
  3. App executes the tool function and builds a tool_result block with output (or error) and tool_use_id.
  4. App re-sends full history (assistant's prior content + new tool_result in a user-role message). Claude integrates and returns text.

Pseudocode

define tools with name, description, input schema
send user message + tools to Claude

loop until stop_reason != "tool_use":
    receive assistant response

    for each tool_use block in response:
        execute tool function with input
        create tool_result block linking to tool_use_id

    append assistant's full prior content to history
    append user message containing all tool_result blocks
    re-send request with updated history

return final text from Claude

Common Misconceptions

  • Myth: You can call the tool yourself and skip sending the result back. Reality: Claude must see the full prior tool_use block and the matching tool_result in history or the loop breaks and it can't match IDs.
  • Myth: Tool results should go in an assistant-role message. Reality: tool_result always goes inside a user-role message, as one item in a content array that can have multiple results.
  • Myth: If a tool fails, throw an exception and let your app handle it. Reality: Return a tool_result with is_error: true so Claude stays inside the loop and can retry or adapt gracefully.

Key Takeaway

The tool-use loop is the heart of agentic AI. Request → tool_use decision → run tool → send result back → Claude answers. Understanding this loop explains everything Claude Code does: its Bash, Edit, Read, Grep tools all follow this protocol. MCP servers and skills add more entries to the same tools array.

Quick Quiz

Q1. Your tool call returns a dictionary with nested fields. How should you send it back to Claude?

A) Send it as a Python object
B) JSON stringify it so Claude can reason about fields
C) Just convert to string
D) Wrap it in another dict

Answer: B — JSON stringify structured returns. Claude reads tool results as strings, but JSON format lets it parse and reason about nested fields.

Q2. Claude emitted two tool_use blocks in one assistant message. How do you respond?

A) Send two separate follow-up requests
B) Run both tools and send one user message with both tool_result blocks
C) Pick one and ignore the other
D) Combine the outputs into a single tool_result

Answer: B — Parallel tool use. Run both and reply with a single user-role message containing both tool_result blocks, each with its matching tool_use_id. Claude consumes them as one turn.

Q3. You want to force Claude to always call your record_signoff tool. Best approach?

A) Set tool_choice: {"type": "auto"}
B) Set tool_choice: {"type": "any"}
C) Set tool_choice: {"type": "tool", "name": "record_signoff"}
D) Set tool_choice: {"type": "none"}

Answer: C — Forcing a named tool requires {"type": "tool", "name": ...}. Option A is default (Claude decides). Option B means "some tool" but not which one. Option D disables tools.
