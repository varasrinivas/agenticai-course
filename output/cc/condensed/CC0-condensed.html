CC0: Getting Started with Claude Code

Master the mental model, install the CLI, and run your first session.

The Big Idea

Claude Code is not a chat plugin or autocomplete tool—it's a command-line orchestration framework that runs in your terminal and executes real work on your codebase using built-in tools (Read, Write, Edit, Bash, Glob, Grep) plus extensible integrations via MCP servers, skills, subagents, and hooks. It edits your filesystem with your permission, runs commands like npm test and git diff, and remembers context across sessions. This transforms Claude from a stateless answering machine into a persistent, tool-using teammate working directly in your project.

Analogy

Think of the difference between a vending machine and a kitchen with a chef. A vending machine takes a coin and dispenses one snack—each turn is isolated. ChatGPT in a browser is a vending machine: you ask a question, you get text you copy-paste. Claude Code, by contrast, is a kitchen with a chef who has read and execute access to your codebase, can run your build tools, remember what happened yesterday, and propose edits you can review and merge. It operates inside your project, not outside narrating recipes.

How It Works

  1. Install the CLI via npm and authenticate with your account (Pro/Team/Enterprise via OAuth, or API key via Anthropic Console).
  2. Open Claude Code in a terminal inside a git repository or any writable directory.
  3. Write a natural-language request: "Add JWT auth to the API" or "Refactor this function to use async/await."
  4. Claude Code reads relevant files, searches the codebase, and proposes edits with diffs you review before accepting.
  5. Use commands like /init, /help, /status, /plan, /model, /clear, /compact, /agents, /hooks to configure behavior and manage sessions.
  6. Reference files with @, switch into plan mode (think-first, edit-later), and resume yesterday's session with --continue or --resume.

Pseudocode

When user opens Claude Code in a terminal:
  1. Authenticate via OAuth (Pro/Team) or API key (Console)
  2. Read repository metadata and optional CLAUDE.md config
  3. Listen for natural-language task prompt
  4. Parse request and identify tools needed (Read, Grep, Bash, Glob)
  5. Execute reads and searches WITHOUT permission per file
  6. Propose edits as diffs
  7. Wait for user approval before writing filesystem
  8. If edit approved: write file, report results
  9. If denied: propose alternative approach
  10. Save session state so --continue or --resume works
  11. Close session OR receive next prompt (multi-turn)
  12. Persist context in CLAUDE.md for future sessions

Common Misconceptions

  • Myth: Claude Code is Cursor or Copilot in VS Code. Reality: It's a terminal CLI that runs independently; it has an optional IDE extension but is not an inline editor. It reads and edits files, runs commands, and remembers state across terminal sessions.
  • Myth: I should just tell it "write the code" and paste the result. Reality: Plan mode (Shift+Tab) is the right first move for risky or unfamiliar work. Let it read the codebase and reason without editing—catch bugs before they exist, not after.
  • Myth: If I close the terminal, my work is lost. Reality: Sessions are saved. Use --continue to reopen the most recent, or --resume to pick a specific named session from the saved list.

Key Takeaway

Claude Code is a tool-using orchestration framework that operates inside your kitchen (your codebase, your terminal, your build tools), not a vending machine narrating recipes from afar. Install it, authenticate, run /init to scaffold a CLAUDE.md, and open your first prompt in plan mode—think before you code.

Quick Quiz

Q1. Which of the following is the strongest mental model for Claude Code?

A) An autocomplete plugin that lives inside your editor.
B) A web chat with copy-paste code suggestions.
C) A CLI that takes natural-language tasks and orchestrates real tools (read, edit, bash, MCP) under your supervision.
D) A read-only documentation assistant.

Answer: C — Claude Code is a tool-using orchestration framework. The vending machine vs. kitchen analogy: it operates in your kitchen rather than narrating recipes from afar.

Q2. You're starting a long session in a new repo. Which command should you run first?

A) /clear
B) /compact
C) /init — generates a starter CLAUDE.md
D) /hooks

Answer: C — /init inspects the repo and produces a CLAUDE.md scaffold—the starting point for project-specific config.

Q3. You closed your terminal yesterday mid-task. Today you want exactly that conversation back, not a different one. What do you run?

A) claude --continue
B) claude --resume — pick the named session from the list
C) claude --new
D) claude /restore

Answer: B — --continue reopens the most recent session, but if you ran multiple yesterday, --resume opens a picker so you can choose the right session.
