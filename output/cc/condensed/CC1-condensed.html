CC1: API Essentials for CLI Power Users

Master models, Messages API, system prompts, temperature, and structured output.

The Big Idea

Claude Code is built on the Messages API, but the CLI hides most of it from you. Understanding the primitives—how models work, how to build conversations, what system prompts do—turns mysteries into straightforward debugging. Every skill, subagent, and hook you write will rely on API concepts. This module exposes the engine bay: model selection, the four required fields of an API request, multi-turn conversation mechanics, system prompts, temperature tuning, streaming, and structured output via tool use.

Analogy

Driving a car works fine until something breaks. That day you need to know what a spark plug and oil pump are. Claude Code is the same: you can ship for months using just the CLI, but the moment a skill won't follow instructions, a subagent picks the wrong model, or a hook returns malformed JSON, you need to understand the Messages API underneath. This module is the engine bay.

How It Works

  1. Pick a model — Opus 4.7 (deep reasoning), Sonnet 4.6 (default), or Haiku 4.5 (fast, cheap). Pin dated IDs in production.
  2. Build a Messages API request — Four required fields: model, max_tokens, messages array (alternating user/assistant), optional system prompt.
  3. Maintain conversation history — To continue a chat, append the previous assistant response and new user message, then re-send the entire array every turn.
  4. Tune with system prompts and temperature — System prompt = stable role/constraints; temperature 0–0.3 for determinism, 0.7–1.0 for creativity.
  5. Get structured data reliably — Don't ask for JSON or prefill; use tool use with forced tool_choice for schema-validated responses.

Pseudocode

function makeAPICall(model, prompt):
  request = {
    model: model
    max_tokens: 1024
    system: "You are a code reviewer"
    messages: [{role: "user", content: prompt}]
  }
  response = call API with request
  return response.content[0].text

function multiTurnConversation():
  history = []
  user_input = "What is Canberra?"
  history.append({role: "user", content: user_input})

  response = call API with history
  assistant_text = response.content[0].text
  history.append({role: "assistant", content: assistant_text})

  follow_up = "And its population?"
  history.append({role: "user", content: follow_up})

  response = call API with entire history
  return response  // Claude remembers Canberra context

Common Misconceptions

  • Myth: The Messages API stores conversation history on the server. Reality: Claude is stateless. You send the entire prior conversation on every request; the messages array is your chapter folder.
  • Myth: You can send two consecutive user messages; the API will concatenate them. Reality: Roles must alternate user/assistant. Two user messages = 400 error; merge them into one message instead.
  • Myth: Asking Claude to "return JSON only" is a reliable way to get structured output. Reality: Text-based prompting is fragile. Tool use with forced tool_choice is the only schema-validated approach that guarantees shape.

Key Takeaway

Every Claude Code feature—skills, subagents, hooks, CLAUDE.md integration—is a wrapper over the Messages API. Understanding model selection, the four required request fields, conversation history mechanics, temperature tuning, and tool-based structured output gives you the mental model to reason about why Claude behaves the way it does, debug edge cases, and write production systems that don't surprise you.

Quick Quiz

Q1. Your hook classifies stack traces as "transient" vs "bug" 50,000 times a day. Which model?

A) Opus 4.7 — high-stakes classification
B) Sonnet 4.6 — safe default
C) Haiku 4.5 — classification is bounded, volume is high, latency matters
D) Whichever the CLI defaults to

Answer: C — Haiku is built for bounded classification at high volume. Picking Opus costs 15x more with no accuracy gain.

Q2. You send messages=[{role:"user", ...}, {role:"user", ...}]. What happens?

A) The two user messages concatenate automatically
B) 400 error — roles must alternate
C) Claude treats the second as a system message
D) The first is silently dropped

Answer: B — The API requires strictly alternating user/assistant turns. Merge extra context into a single user message.

Q3. You're calling Claude in a CI script that diffs two JSON files. What temperature?

A) 0.0 — classification wants reproducibility
B) 0.7 — room to think creatively
C) 1.0 — for thoroughness
D) Doesn't matter; CI is non-interactive

Answer: A — Determinism is the whole point of CI. Temperature 0 gives stable verdicts across runs, avoiding flaky failures.
