Prompting Patterns & Context

The difference between a mediocre AI session and a productive one is almost entirely about context. This module teaches you how to give Gemini CLI exactly the information it needs — using @ mentions, slash commands, multiline input, the memory system, and approval gates — so you stop copy-pasting and start getting work done.

What You'll Learn

  • Use @file, @url, and @./ to inject context into any prompt without copy-pasting
  • Know every built-in slash command and when to reach for each one
  • Send multi-line prompts and pipe file content directly from the terminal
  • Set up global, project, and session memory so Gemini learns your preferences
  • Understand the approval gate flow and make smart decisions about what to allow
  • Apply five context-budget rules to keep sessions fast and focused

@ Mentions — Giving Gemini Eyes on Your Code

Analogy — The Annotated Brief

Before working with a co-worker on a document, you don't read the whole thing aloud over the phone — you send them the file. The @ syntax does exactly that: it hands Gemini specific files, directories, or web pages so the conversation starts with shared context. Without it, you're asking someone to fix a bug they've never seen.

The pain without this: you manually copy hundreds of lines into the prompt, lose formatting, and hope nothing important is cut off. The mapping to Gemini: @src/app.js is the equivalent of attaching the file to an email — it arrives intact, with path context included.

Technical Definition — @ Mentions

An @ mentionA special prefix in a Gemini CLI prompt that instructs the CLI to read and inject the contents of a file, directory, or URL into the prompt before sending it to the model. The resolved content counts against your context window budget. is a shorthand that resolves to file or URL contents at prompt-send time. Gemini CLI reads the referenced path, encodes its contents, and prepends them to your message before the API call. The model sees a single expanded message; it never directly accesses your filesystem.

File Mentions

The simplest form: prefix any relative or absolute path with @.

Gemini CLI prompt
@src/app.js What does this file do?

@package.json @src/index.js Are these consistent?

@./  Summarize this entire project
WHAT: Each @path token is replaced with the file's full contents before the prompt reaches the model.
WHY: The model has no knowledge of your local filesystem — you must bring the context to it, not the other way around.
GOTCHA: @./ sends every non-ignored file in the current directory. On a large repo this can exceed your context windowThe maximum amount of text (measured in tokens) that a model can process in a single API call. Gemini 2.0 Flash has a 1M token context window, but larger contexts slow down responses and cost more. budget in seconds. Always prefer specific paths.

URL Mentions

Pass @https://... to fetch a web page or API spec and inject its contents inline.

Gemini CLI prompt
@https://api.example.com/openapi.json Generate a TypeScript client for this API
WHAT: Gemini CLI fetches the URL at prompt time, then includes the response body as context.
WHY: This is the fastest way to generate clients, validators, or documentation from live API specs — no download, no copy-paste.
GOTCHA: HTML-heavy pages become very large when decoded. Prefer raw/JSON endpoints (like OpenAPI or GitHub raw URLs) over marketing pages.

Multi-File Patterns

You can chain as many @ references as you need in a single prompt:

Gemini CLI prompt
@src/models/user.js @src/routes/users.js @tests/users.test.js
Find any inconsistencies between the model, routes, and tests
WHAT: All three files are injected, each with their path as a header so the model knows which content came from where.
GOTCHA: Each additional file grows the tokenThe basic unit of text that models process. Roughly 1 token ≈ 4 characters or ¾ of a word. A 500-line file typically costs 3,000–5,000 tokens. Monitor token usage with /stats. count. Check /stats after a few multi-file sessions to calibrate how large your typical files are.

Why It Matters

Teams using context-aware prompting (injecting relevant files directly) see 40–60% fewer follow-up clarification turns compared to free-form prompts. The model doesn't guess at your variable names, import paths, or existing patterns — it reads them. That difference is the gap between a suggestion and a runnable solution.

Now that Gemini can see your code, let's look at the commands that control the conversation itself.

Slash Commands — The Control Panel

Analogy — The IDE Command Palette

Every IDE has a command palette (Ctrl+Shift+P in VS Code) — a searchable list of every action the editor can perform. Slash commands are Gemini CLI's equivalent: instead of navigating menus or configuring files, you type a short command at the prompt and something happens immediately.

The pain without this: you'd need to exit the session, edit config files, and restart to change behavior. The mapping: /model gemini-2.5-flash switches the active model mid-conversation, the same way the command palette lets you change the color theme without restarting VS Code.

Multiline Input & Code Blocks

The terminal's single-line input can feel limiting when you need to paste a requirements doc, a stack trace, or a multi-function code snippet. Gemini CLI gives you two clean solutions.

Triple-Quote Wrapping

Wrap multiline content in """ delimiters. Everything between the opening and closing triple-quotes is treated as a single block — newlines, indentation, and blank lines are preserved.

Gemini CLI — triple-quote wrapping
"""
Here is our onboarding requirements document:

Users must be able to register with email and password.
Passwords must be at least 12 characters.
Two-factor authentication is optional but recommended.
After registration, users receive a verification email.
Unverified accounts expire after 48 hours.
"""
Please extract all user stories from this as a numbered list.
WHAT: The triple quotes signal to the CLI that the block spans multiple lines — the prompt isn't sent until the closing """ is entered.
WHY: For long context (requirements, error logs, config dumps), triple-quoting is cleaner than file mentions when you don't have the content in a file yet.
GOTCHA: Very large pastes — think 50+ KB of logs — should use @file instead. Triple-quoting a giant log means the whole thing lands in context without any path metadata.

Piping File Content

For non-interactive use (scripts, CI pipelines), pipe content directly into gemini using your shell.

# Pipe a file to gemini with a prompt flag
Get-Content requirements.txt | gemini -p "Extract user stories from this"

# Pipe build output to check for issues
npm run build 2>&1 | gemini -p "Summarize any errors or warnings"

# Pipe API response for analysis
Invoke-RestMethod https://api.example.com/status | ConvertTo-Json | gemini -p "Is anything wrong?"
# Pipe a file to gemini with a prompt flag
cat requirements.txt | gemini -p "Extract user stories from this"

# Pipe build output to check for issues
npm run build 2>&1 | gemini -p "Summarize any errors or warnings"

# Pipe API response for analysis
curl -s https://api.example.com/status | gemini -p "Is anything wrong?"
WHAT: The -p flag sets the prompt; stdin becomes the user message body. Gemini CLI reads stdin when it's not a terminal (i.e., when piped).
WHY: This unlocks scripting and CI integration. You can add AI analysis to any pipeline that produces text output without changing the upstream command.
GOTCHA: Piped sessions run in non-interactive mode — slash commands and approval gatesInteractive prompts that appear when Gemini CLI wants to run a shell command or modify a file. In non-interactive (piped) mode, gates cannot display — use --yolo only in trusted CI pipelines. don't work. If the model wants to run a command, it will be blocked. Add --yolo only when you trust the full pipeline.

Checkpoint

You now have three ways to inject content: @path for files you have on disk, @url for live web content, and triple-quotes or piping for content you're generating on the fly. The rule of thumb: if it's a file, use @; if it's temporary text, use triple-quotes; if it's a pipeline, use piping.

You can give Gemini context for the current session. Now let's make preferences stick permanently.

The Memory System

Analogy — The Three Notebooks

Imagine you have three notebooks: a pocket-sized one you carry everywhere (global), a project binder on your desk (project), and a sticky note on your screen for today's work (session). When you sit down, you read them in order: pocket notebook first, then binder, then sticky. Later entries can override earlier ones — if the sticky note says "use Postgres" but your pocket notebook says "use SQLite", the sticky note wins for today.

Gemini's memory works identically: global loads first, project overrides it for the current directory, and session context is king for this conversation only.

Three Memory Tiers

🌐

💬

The in-context conversation history. Lost when you /clear or quit. Highest priority — any instruction in the current conversation overrides both files.
this session
Technical Definition — GEMINI.md

GEMINI.mdA Markdown file that Gemini CLI loads automatically as a system-level instruction. The global version lives at ~/.gemini/GEMINI.md; the project version lives at the root of your project directory. Both are plain Markdown — write instructions, preferences, and context in natural language. is a plain Markdown file that Gemini CLI injects as a system-level instruction before any user message. Think of it as a persistent "always remember this" note that lives outside any single conversation. The global version applies everywhere; the project version applies only when you're inside that directory.

The fastest way to teach Gemini your preferences is /memory add. Here's what power users store:

# Save coding standards
/memory add Always add error handling to generated code

# Save personal context
/memory add My name is Alex, use it in greetings

# Save platform awareness

# Save project conventions

WHAT: Each /memory add call appends a bullet point to ~/.gemini/GEMINI.md.
WHY: You should never have to say "I use TypeScript" more than once. Preferences that live in global memory free every future prompt from repetitive context-setting.
GOTCHA: Global memory is injected into every session. If it grows very large (500+ tokens), it eats into your context budget. Audit with /memory show and trim with /memory clear + re-add if needed.

You can also read and edit the memory files directly:

# Open global memory in Notepad

# Or view it directly in the terminal

# Open project memory (create if absent)
notepad .\GEMINI.md
# View global memory
cat ~/.gemini/GEMINI.md

# Edit it
nano ~/.gemini/GEMINI.md
# or
code ~/.gemini/GEMINI.md

# Create/edit project memory
touch ./GEMINI.md && code ./GEMINI.md
Why It Matters

Teams that invest 10 minutes setting up a project GEMINI.md with naming conventions, tech stack, and style preferences see consistent outputs from day one — no one has to re-explain the architecture in every session. Individual developers with a well-tuned global memory report cutting "re-prompt overhead" by over 50% in day-to-day use.

Approval Gates & Shell Execution

Analogy — The Building Permit

A contractor doesn't knock down walls without showing you the plan first. The building permit process exists because some actions are reversible and some aren't — you want a human sign-off before the irreversible ones. Gemini CLI's approval gate is that permit process: it proposes, you decide.

The pain of no gates: an automated tool runs rm -rf node_modules when you just wanted it to clean up temp files. The mapping: the gate intercepts every shell command and file edit, shows you exactly what it plans to do, and waits for your explicit OK.

When Gemini CLI wants to run a shell command or edit a file, it presents an approval gateAn interactive confirmation prompt that appears before Gemini CLI executes any shell command or file modification. You can approve once, always allow, see details, or reject. The --yolo flag disables all gates — use only in trusted automated environments.:

? Run command:
npm install express
[y] Yes [n] No [a] Always allow [d] Details

Understanding Each Option

  • [y] Yes — approve this one command; you'll be asked again next time the same type of command appears.
  • [n] No — reject the action. Gemini will know it was blocked and may suggest an alternative approach.
  • [a] Always allow — add this command pattern to the auto-approve list for this session. Useful for repeated build commands.
  • [d] Details — expand the full command with all flags, environment, and working directory before deciding.
When to Be Careful

Always inspect before approving commands that contain: rm / Remove-Item, DELETE, DROP TABLE, truncate, --force, wildcards (*) in paths, or anything touching ~/.ssh, .env, or production environment variables. One [a] Always allow on a destructive command pattern can cause real damage.

Safe to Always Allow

Low-risk patterns you can confidently approve every time: npm install, git status, git diff, tsc --noEmit (type-check only), npm test, pip install -r requirements.txt.

The --yolo Flag

The --yolo flag disables all approval gates — every command runs automatically without asking.

# CI/CD pipeline — no terminal for interactive prompts
gemini --yolo -p "Run tests and fix any failures"

# Scaffolding a new project (you're in an empty dir, nothing to break)
gemini --yolo -p "Scaffold a Node.js Express API with TypeScript"
# CI/CD pipeline — no terminal for interactive prompts
gemini --yolo -p "Run tests and fix any failures"

# Scaffolding a new project (empty dir, nothing to break)
gemini --yolo -p "Scaffold a Node.js Express API with TypeScript"
GOTCHA — Never Use --yolo in Production Workflows

--yolo is appropriate in two scenarios: isolated CI containers where the entire filesystem is ephemeral, and empty scaffolding directories where nothing exists to destroy. Using it against a working codebase, a database connection, or any environment with real state is the fastest way to cause unrecoverable damage. The gates exist for your protection — keep them on by default.

Context Best Practices

The model's performance is directly proportional to the quality and relevance of its context — not its size. Here are five rules that keep sessions fast, focused, and cost-effective.

Rule 1 — Use @./ Sparingly

@./ dumps your entire project into context. On a 50-file Node.js project that's easily 100,000+ tokens — a minute of processing time and real API cost. Use @./ only for genuine "understand my whole project" questions. For focused tasks, prefer specific directories: @src/auth/, @tests/.

Rule 2 — Be Specific with Paths

@src/auth/ is almost always better than @src/ when you're working on authentication. The model does better analysis with 3 highly relevant files than with 30 files that are mostly irrelevant to the question.

Rule 3 — Stable Instructions Belong in GEMINI.md

Any instruction you've typed more than twice ("always use TypeScript", "this project uses Tailwind CSS", "our API base URL is…") belongs in GEMINI.md. Prompts are for questions; GEMINI.md is for standing orders.

Rule 4 — Check Token Usage with /stats

Run /stats before sending prompts that include large files. If you're already at 500k+ tokens in context, consider whether you need all that history or whether a /clear + focused context would give better results at lower cost.

Rule 5 — /clear When Switching Tasks

Stale context is one of the most common sources of confusing model behavior. If you've been debugging a payment bug for an hour and now want to work on the UI, /clear first. The conversation history about the payment flow is noise for a CSS problem.

You can also do a dry-run token count on any prompt before spending API quota:

# Count tokens without making an API call
gemini --print-tokens "@src/auth/ Explain the authentication flow"

# Sample output:
# Prompt tokens: 8,432
# (no API call made)
# Count tokens without making an API call
gemini --print-tokens "@src/auth/ Explain the authentication flow"

# Sample output:
# Prompt tokens: 8,432
# (no API call made)
WHAT: --print-tokens resolves all @ mentions, counts tokens in the constructed prompt, and exits without calling the API.
WHY: Use this to calibrate your intuition. After a few runs you'll develop a sense for how many tokens your typical files cost, and you'll naturally reach for more specific paths.
Why It Matters — The Economics of Context

Gemini 2.0 Flash charges per million input tokens. A developer who sends @./ on every question might easily spend 10× more than one who uses targeted @src/feature/ mentions. More importantly, larger contexts have diminishing returns — the model's attention is finite, and burying your question in 200,000 tokens of unrelated code often produces worse answers than a clean prompt with 5,000 tokens of relevant context.
