Universal Agent Loop pseudocode 
# The universal agent loop — every agent is a variation of this

messages = [user_question]
iters, tokens, errors = 0, 0, 0

WHILE iters < MAX_ITERS AND tokens < BUDGET AND errors < THRESHOLD:

    response = CALL Claude(tools=tool_list, messages=messages)

    messages.append({role: "assistant", content: response.content})
    tokens += response.usage.total

    IF response.stop_reason == "end_turn":           ← happy path ✓
        RETURN final_text(response)

    results = []
    FOR block IN response.content:
        IF block.type == "tool_use":
            out = RUN(block.name, block.input)
            results.append({tool_use_id: block.id, content: out})

    messages.append({role: "user", content: results})   ← BOTH sides required
    iters += 1

RAISE "max iterations exceeded"                        ← safety rail fires
5 stop rails Three guards fire before each Claude call: iteration cap, token budget, consecutive error threshold. Natural completion (end_turn) is the only signal meaning "success" — the others are safety nets for runaway loops.
end_turn Never parse Claude's text to detect completion. stop_reason == "end_turn" is the only reliable signal — scanning natural language for "I'm done" breaks across model versions and prompt changes.
both sides Append both the assistant response and the tool_results before the next API call. Forgetting either causes the API to reject the request. Each tool_result's tool_use_id must exactly match its tool_use's id.
safety rail Start with MAX_ITERS = 10 for most tasks, up to 25 for research agents. A partial result at 8/10 is valuable — return what you have with a note rather than nothing. The rail catches confused loops, not successful completion.

30 Interview Flash Cards

Review these before the call
Q: What is a true AI agent? (technical)
A program combining: (1) LLM as reasoning engine, (2) tools to interact with the world, (3) a loop that keeps it thinking and acting until the task is complete. The loop is the entire agent.
Q: Single question separating agents from workflows
"Who decides what happens next — your code, or Claude?" Level 3 = Claude decides at runtime which tool, which args, when to stop. Your code provides tools; Claude provides the brain.
Q: Litmus test for a true agent
Replace LLM with hardcoded responses. If program still works — NOT an agent. Level 3 breaks because Claude's runtime decisions can't be hardcoded. That fragility IS the proof.
Q: Two phases of LLM inference
Prefill: all input tokens processed in parallel; drives TTFT; scales with prompt length. Decode: one token at a time; drives TPS; ~constant per model. Prompt caching collapses repeated prefill.
Q: Default temperature for agents and why
temp=0. At temp 0.8, an agent routing 5K emails/day produces 150–400 unpredictable routing decisions. Reproducibility, debuggability, auditability beat surprise in agentic systems.
Q: Where to cut tokens — priority order
1) Cap max_tokens (output is 3–5× more expensive). 2) Trim system prompt (sent every call). 3) Summarize history at 60–70% utilization. 4) RAG instead of full docs. 5) Tier down to Haiku.
Q: The universal agent pattern (pseudocode)
messages=[question]. WHILE True: response=CALL Claude. IF end_turn → RETURN text. FOR each tool_use → run tool, append result. LOOP. Plus 5 stop rails (iters, tokens, errors, time, natural).
Q: #1 tool-use bug to watch for
Forgetting to append BOTH the assistant response AND the tool_results before the next API call. Also: each tool_result's tool_use_id must exactly match the tool_use's id.
Q: How many tools per request? Why?
Cap at 4–6. Selection accuracy: 97% at 3 tools → 61% at 18 tools. Each schema burns 200–500 input tokens. Beyond 6, split into specialized subagents (M14).
Q: Tool description — what must it include?
WHAT it does (strong verb + concrete object). WHEN to use vs. sibling tools. WHAT it returns (shape/format). Each property also needs its own description with an example value.
Q: Empty result vs error — why does it matter?
{results:[]} = "I checked, nothing matched" → Claude stops. {isError:true} = "I couldn't even check" → Claude asks for help. Conflating causes catastrophic decisions.
Q: MCP vs A2A — one sentence each
MCP = agent↔tool (vertical, Anthropic Nov 2024): how one agent connects to its tools. A2A = agent↔agent (horizontal, Google→Linux Foundation 2025): cross-org delegation with auth. Real systems use BOTH.
Q: 5 stop conditions for a ReAct loop
1) Natural completion (end_turn) — ONLY signal meaning success. 2) Max iterations (5–15). 3) Token/cost budget. 4) Error threshold (2–3 consecutive failures). 5) Wall-clock timeout (30s–2min).
Q: Why thought traces matter
The ACT of generating reasoning text improves Claude's next decision by 20–30%. Don't suppress to save tokens. Do summarize old entries in long sessions. Also provides audit log for compliance.
Q: Plan-Execute vs ReAct — cert exam trap
Plan-Execute: steps can be known before ANY tool runs — brittle when reality differs. ReAct: steps emerge from results — adapts to surprises. Choose by whether steps are knowable before execution.
Q: 8 agent patterns in order of complexity
P1 Single-Turn · P2 ReAct · P3 Plan-Execute · P4 Router · P5 Fan-Out · P6 Pipeline · P7 Supervisor+Workers · P8 Auto+HITL. Pattern choice can swing API bill 10–50× in production.
Q: Subagent vs sub-prompt
A subagent is a separate agent invocation: own system prompt, own small toolset, blank context window, returns structured JSON. Isolation IS the feature. Never let subagents call each other directly.
Q: The coordinator's 4 jobs
1) Route (which subagents). 2) Brief (self-contained task string, resolve pronouns). 3) Collect (structured result, handle errors). 4) Synthesize (one answer). Coordinator owns history; subagents don't.
Q: Input guardrails — 5 layers in order
1) Rate limit (0.1ms, $0). 2) PII detect+redact (regex+Luhn+NER). 3) Injection classifier (separate clean-context Claude call). 4) Schema validation (Pydantic, $0). 5) Allow/deny/log. Fail CLOSED on errors.
Q: Why prompt injection is like SQL injection
Same channel, same vulnerability: data and instructions share one untrusted channel. Fix lives OUTSIDE the model — separate-context classifier on every input AND every tool result (indirect injection).
Q: Output guardrails — 3 checks, cheapest first
1) Format ($0 local parse). 2) Hallucination (~$0.003 RAG-grounded verifier). 3) Toxicity (~$0.005 Claude-as-judge). Skip downstream if upstream blocks. Three verdicts only: allow, redact, block.
Q: 3 HITL gates and when to use each
Approval: irreversible actions. Modification: output needs human voice. Escalation: policy gap/capability limit. Tier on blast radius and reversibility — NOT transaction volume or model confidence score.
Q: Circuit breaker — 3 states
CLOSED (normal) → N failures → OPEN (all→fallback, 60s cooldown) → HALF-OPEN (1 probe) → pass→CLOSED or fail→OPEN with 2× backoff. Different thresholds per failure type.
Q: Why assertEqual fails for agent testing
3 breaks: non-determinism (same prompt → different output), trajectory matters (15 tools for 2-tool job = broken), quality is spectrum not binary. Use rubric scoring on curated golden dataset stratified by category.
Q: 4 evaluation metrics for agents
Task completion rate. Tool accuracy (right tool, right params). Response quality 1–5 (Claude-as-judge). Efficiency (tokens, calls, latency). ALWAYS stratify by category — aggregate hides broken subcategories.
Q: RAG pipeline — 5 steps
1) Ingest (chunk, embed, store). 2) Query (embed question, top-k cosine). 3) Augment (inject chunks into prompt). 4) Generate (Claude answers grounded). 5) Verify (check claims vs sources). Hybrid search beats pure vector.
Q: "Lost in the middle" effect
Claude's attention is strongest at START (system prompt) and END (latest message). Facts buried in a long history get less attention. Put critical instructions at START or END — never in the middle of long docs.
Q: Rate limiting — token bucket mechanics
Bucket holds N tokens; each request consumes 1; refills at R/second. Burst-friendly. Implement per user, per endpoint. Sliding window not fixed window (exploitable boundary). Back with Redis in production.
Q: Observability — print statements vs production
Print statements vanish on restart. Production = structured JSON logs + distributed traces + dashboards. Key: answer "why did Claude pick tool X on request Y at 3:14pm last Tuesday?" with trace_id.
Q: 60-second "whole arc" talking point
