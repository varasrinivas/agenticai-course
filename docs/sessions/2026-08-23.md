## The recurring lesson: verify identifiers at the source

Three separate identifier errors, all produced the same way — inferred from a neighbouring
example instead of looked up. Each took one `grep` or one fetch to settle.

1. **`context: fork`** — previously written off as not a real SKILL.md field because it
   appears in none of the 58 official marketplace skills. The CLI binary has
   `context:Dr(["inline","fork"])`. Absence from examples is not evidence.
2. **`claude-haiku-3-5`** — Claude 3.5 Haiku written in the 4.x tier-first convention. The
   real ID is tier-last, `claude-3-5-haiku-20241022`. Shipped inside a copy-pasteable
   `claude --model` command.
3. **`us.anthropic.claude-sonnet-4-6-20250514-v1:0`** — a 4.6 name welded to Sonnet 4's
   date plus a suffix 4.6 doesn't use. AWS says `us.anthropic.claude-sonnet-4-6`, no date,
   no suffix.

**I was also wrong in the opposite direction**, which matters more. I flagged
`claude-sonnet-4-6` and the `opus-4-x` IDs as stale; the binary shows all of them are real.
Had the "full Claude 5 family" option been taken, ~1,300 valid IDs across six courses would
have been rewritten to fix a problem that didn't exist. The narrow scope decision prevented
that.

And **the first Bedrock fix was itself wrong** (`aaf2fe7`): it corrected a bad date on a
form that shouldn't carry a date at all. `587b9e7` supersedes it.

Both verification methods are now written into `prompts/19-sdk-tier-policy.md` with the
exact commands — the SKILL.md frontmatter schema (`ea68827`) and model IDs across direct /
Bedrock / Vertex (`1fd3e14`).

## Two rules replaced because they were measuring the wrong thing

**`.gitattributes`** (`8184caa`). Every generator writes LF; with `core.autocrlf=true` and
no attributes file, git checked them back out as CRLF, so each build left ~70 pages
"modified" with an empty diff. That noise buried real work — the Capstone 9 fixes touched 6
files and appeared as 77. `* text=auto eol=lf` makes the worktree byte-identical to the
index. Verified: a full rebuild now leaves **zero** files modified.

**The 200KB size cap** (`7e3aca0`). Measured first: across 191 pages, median 101KB, p90
179KB, max 265KB. The cap failed ~10% of pages and failed the wrong ones — the largest
module is 36KB CSS, 37KB JS, **zero embedded assets**, 192KB prose. The rule penalized the
depth `CLAUDE.md` demands everywhere else. Replaced with a check on what it was guarding:
asset imports must resolve to the four allowed hosts, and no `data:` URI may carry a
payload. Verified satisfiable corpus-wide first — which caught two false positives in my own
draft (hyperlinks in prose aren't imports; zero-length base64 in a code sample isn't an
asset).
