## Two rules replaced because they were measuring the wrong thing

**`.gitattributes`** (`e21c538`). Every generator writes LF; with `core.autocrlf=true` and
no attributes file, git checked them back out as CRLF, so each build left ~70 pages
"modified" with an empty diff. That noise buried real work — the Capstone 9 fixes touched 6
files and appeared as 77. `* text=auto eol=lf` makes the worktree byte-identical to the
index. Verified: a full rebuild now leaves **zero** files modified.

**The 200KB size cap** (`f4ea03c`). Measured first: across 191 pages, median 101KB, p90
179KB, max 265KB. The cap failed ~10% of pages and failed the wrong ones — the largest
module is 36KB CSS, 37KB JS, **zero embedded assets**, 192KB prose. The rule penalized the
depth `CLAUDE.md` demands everywhere else. Replaced with a check on what it was guarding:
asset imports must resolve to the four allowed hosts, and no `data:` URI may carry a
payload. Verified satisfiable corpus-wide first — which caught two false positives in my own
draft (hyperlinks in prose aren't imports; zero-length base64 in a code sample isn't an
asset).

## Correcting the tier index, and what it was worth

The index claimed CAPSTONE-1..5 and 7 were Tier 3 and spec-driven. Surveying every lab showed
none of them were:

| | Index said | Reality |
|---|---|---|
| C1–C3 | Tier 3, spec-driven | raw `anthropic`, no spec, no SDK |
| C4 | Tier 3 | raw solutions; SDK only in `sdk_tests/` — the harness the policy itself cites |
| C5 | Tier 3 | raw solutions; domain-C spec describes an SDK build **no code implements** |
| C6 | Tier 1 | correct — zero LLM calls anywhere |
| C7 | Tier 3, "already spec-driven by name" | three module pages and **no lab at all** |
| C8, 8B, 9 | Tier 3 | correct |

Measured before and after, running PASS 6 across all ten capstones:

```
critical findings: 5  →  0
```

None of that came from lowering a bar. Every finding was the index describing a lab that did not
exist; the labs are unchanged, and the three real Tier 3 capstones still have to prove it per
capstone (solution imports the SDK, spec present) and do.

Two consequences that were not obvious going in. `validate-capstone.md` hardcoded the same wrong
assignment, and its own rule says the tier policy wins in a disagreement — so leaving it
would have been a documented bug. And the Tier 1 rule *"flag a capstone that imports the Agent
SDK"*, applied to the corrected index, would have fired on C4 and C5 for the **sanctioned**
pattern. Without a carve-out scoping that check to `solution/`, correcting the index would have
swapped five false criticals for two new ones.

**A stale table is worse than no table.** Five recurring criticals that are really one wrong row
is the fastest way to teach people to ignore a validator.

Fixed in the same pass: `generate-capstone.md` wrote to `output/` rather than
`output/courses/claude-agents/`, never read the tier policy, and used "Tier 1/2/3" for
*deployment* in a file that now also cites SDK tiers. `labs/README.md` stopped at Capstone 6 and
claimed every capstone has three domain variants. M23 framed the series as "the five projects",
so a student could finish it without learning 6–9 exist.
