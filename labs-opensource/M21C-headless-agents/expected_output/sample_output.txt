      {"line": "... connection pool exhausted, 0 free of 50", "reason": "db saturation", "severity": "high"},
      {"line": "... HTTP 500 on /api/orders (db timeout)", "reason": "user-facing errors", "severity": "high"},

$ echo "exit=$?"      # PIPESTATUS of the agent, before jq
exit=0

(Model output is NOT deterministic. Mistral may flag fewer/more lines or rate
the pool-exhaustion + HTTP 500 pair as `critical` instead of `high` — in which
case the agent raises NeedsReview and exits 3, and the envelope's data is still
attached so the review queue has context. Both are correct outcomes; the
CONTRACT — one JSON object on stdout, logs on stderr, exit in {0,1,2,3} — is what
must hold every time.)


$ cd starter && bash run_triage.sh sample.log ; echo "wrapper exit=$?"
[triage] analyzing 10 log line(s)
[triage] done in 7180ms, exit=0
[wrapper] OK -> reports.jsonl
wrapper exit=0

(The wrapper captured the agent's exit code and routed the JSON to reports.jsonl.
Had the agent exited 3, it would have gone to review_queue.jsonl instead; exit 2
would log + escalate without retrying. The wrapper itself always exits 0 so cron
does not treat a routed result as its own failure.)
